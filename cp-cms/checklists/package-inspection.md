# CMS Package Inspection Checklist

- Identify CMS version/task type if available and the exact loader/repository convention.
- Locate task metadata, statements, tests, scoring data, validators/checkers, graders/managers/stubs, public headers, and solutions.
- Distinguish admin-controlled sources from contestant-visible templates.
- For Communication, identify process count, manager, stubs, communication channels, and manager-output path.
- Identify the trusted full solution/oracle from evidence; do not perform deep solution-proof analysis here.
- Preserve existing testcase IDs/subtask mappings before changing them.
- If testcase semantics need substantial redesign, use `cp-test-case` rather than recreating that methodology here.
